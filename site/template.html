OpenTelemetry Who's Who

Every SIG, every repository, and the people who run them: maintainers, approvers, triagers, emeritus, component code owners, TC sponsors and GC liaisons. Search a GitHub handle to see everything one person owns.

New: Ownership Check — five plain answers about who looks after each Collector component, with the files behind every answer.

Where this comes from

  • SIGs, their repositories, meetings, Slack, TC sponsors and GC liaisons: workstreams.yml and people.yml in open-telemetry/community. Committees: community-members.md in the same repo.
  • Maintainers, approvers, triagers and emeritus: the role sections of each repository's README.md (or CONTRIBUTING.md, where the SIG keeps them there).
  • Code owners: each repository's CODEOWNERS, plus .github/component_owners.yml where a contrib repo uses it for reviewer assignment.
  • Components: .github/component_labels.txt maps each component to its issue label, and each component's metadata.yaml gives its stability, active code owners and whether it is seeking new ones. Open issue and PR counts come from the GitHub API, once a day.
  • Contributors: merged PRs from the GitHub API, with who wrote, merged and approved each one. For longer history and company or country breakdowns, see CNCF DevStats for OpenTelemetry.

Known gaps

  • Only repositories assigned to a SIG in workstreams.yml are included. Archived or unassigned repos in the org are not.
  • Live GitHub team membership (for example @open-telemetry/collector-contrib-approvers) is visible only to org members, so the README lists are used as the public record. A README can lag a team change.
  • Some repos defer to another list (for example to the Technical Committee or the parent SIG repo) and show no names of their own.
